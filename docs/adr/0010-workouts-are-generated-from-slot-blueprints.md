# Workouts are generated from slot Blueprints, not composition caps

The deterministic generator built a day's shape emergently: a three-pass greedy loop constrained by four cap families (`max_exercises_per_pattern` + overrides, `max_exercises_per_region`, `max_compound_by_region`, `max_total_exercises`), a complementary-pattern import with ARMS special-casing, a muscle-group ordering table, and a set-distribution round-robin. Every balance bug (ADR-0009's alias removal, the arm-day cap overrides, the 2026-10-25 set-distribution fix) was a patch on emergence, and the day's shape was only knowable by running the code. We replace all of it with declared shape: six Blueprints (Push, Pull, Upper, Lower, Full Body, Arms) in `config/workout_blueprints.php`, each an ordered list of Slots — movement role (patterns, optional angles), Tier, sets, rep range. Selection becomes: resolve blueprint, fill each slot from its pool, done. Balance is guaranteed by construction, weekly per-muscle volume is auditable by reading config, and a CI guard test (three equipment presets: full gym at waterfall level 0, dumbbell+bodyweight ≤ 2, bodyweight ≤ 3 with a documented skip-exception list) keeps the catalog honest.

## The mechanism

- **Resolver**: the request's `target_regions` map to a Blueprint:

  | request | blueprint |
  |---|---|
  | `[UPPER_PUSH]`, `[UPPER_PUSH, ARMS]` | PUSH |
  | `[UPPER_PULL]`, `[UPPER_PULL, ARMS]` | PULL |
  | `[UPPER_PUSH, UPPER_PULL]`, `[UPPER_PUSH, UPPER_PULL, ARMS]` | UPPER (its arms slot is tier 3, so arm work arrives only at Extended) |
  | `[LOWER]`, `[LOWER, CORE]` | LOWER |
  | `[]`, `[FULL_BODY]`, all regions, any push/pull/lower 3-region combo | FULL_BODY (focus = first region; empty or the literal FULL_BODY region ⇒ Push focus, reorder only — one blueprint, no variants) |
  | `[ARMS]` | ARMS |
  | anything else (API requests, and admin-defined splits such as the 2-day balanced split's push+lower and pull+lower days; mobile presets can't produce one) | per-region Fragments, concatenated in request order, tier-filtered, then trimmed to the tier's set budget region by region: the region holding the most sets loses its last slot first (ties: the later-requested region), so a requested region is trimmed to nothing only once every region is already down to its first slot. Composed days never get the Extended +1-set bonus — the budget is their volume mechanism (#112) |

  A single region maps to the full day type: `[UPPER_PUSH]` yields PUSH including its ARMS-region triceps slot — the region list is a lookup key, the Blueprint defines content.

  Every requestable region declares a Fragment, so no region can silently shrink a day. FULL_BODY is requested alone or not at all: a full body is a full body, and a request or split combining it with other regions is rejected as invalid. There is no CONDITIONING region; it served no exercise and no day, and was removed rather than special-cased.
- **Session length is a fixed menu, and Tiers do the scaling**: durations are exactly 30/45/60/90/120 (what mobile already offers; Generate/Regenerate/ProfileUpdate validation tightens to this set, admin preview follows). 30 ⇒ Express (tier-1 slots only), 45/60 ⇒ Standard (tiers 1–2), 90/120 ⇒ Extended (all tiers, +1 set on the first two tier-1 slots; 120 adds nothing beyond 90). A migration moves stored off-menu durations to the nearest menu value in the same tier (75 ⇒ 90), so every stored duration is one a client can echo back; tier resolution stays threshold-based (`<40`, `40–60`, `>60`) as a safety net. `minutes_per_set`, `exercise_count_by_goal` and the set-distribution logic die.
- **Filling**: one pool query per plan — a plan's days share their constraints, and a single generated session is a one-day plan — and one batched history lookup for every exercise the plan picked (equipment/beginner/partner/user filters, training styles among them: a request with no equipment selection defaults to the BODYBUILDING catalog, and a client-sent BODYBUILDING-only default is dropped when the selection includes functional equipment — the legacy generator's semantics, carried over verbatim in #113), partitioned per slot in memory; pick = shuffle, excluding already-picked IDs (`selection_priority` descending is wired as the pre-shuffle sort but inert while uncurated). User-supplied `movement_patterns`/`angles`/`equipment_types` remain hard pool constraints. An empty slot walks the Relaxation Waterfall — drop angle; drop pattern keeping region + compound/isolation class; bodyweight equivalents; skip — and a skipped slot's sets go +1 to the earliest filled slots (cap: slot sets + 1). Every non-zero relaxation is logged with `slot_key` and level.
- **Prescriptions**: a generated row always stores its Slot's sets and rep range, the range goal-shifted on **compound Slots only** (strength ⇒ 4–6, fat loss ⇒ 8–12, others ⇒ slot base; isolation Slots always keep the slot range). The Slot's class, not the filling exercise's, decides compound vs isolation treatment everywhere on the row — goal shift, rest floor, deload reps — so a split squat filling `quad_iso` is treated as an isolation. Rest is the Prescription's goal-scaled Default Rest (ADR-0009). The member's logged history outranks these defaults only for Working Weight and rest, never for the stored sets or rep range; progression then judges each performance against its Logged Range (ADR-0011). The ADR-0009 matrix survives solely for non-generated rows (manual templates, user-added session exercises). Starting weights, double progression and deload structure (ADR-0007/0008) are untouched.
- **Traceability**: `workout_template_exercises` and `workout_session_exercises` gain nullable `slot_key`, written by the generator and carried from template row to session row when a session starts from a template, not yet exposed in API resources. The future "swap exercise" feature is exactly `pool(slot_key) − current`, out of scope here.

## Consequences

- **60-minute sessions drop from ~20 to ~15 sets.** Deliberate: Standard tier is the quality-volume target; do not "fix" this back by remapping 60 to Extended.
- Day shapes are uniform per blueprint by design; variety lives in pool shuffle, per split row (duplicate day types in one split fill independently), frozen within a Mesocycle as before.
- Two curls or two extensions on an Arms day is now by design (heavy + finisher slots); the `ELBOW_*` per-pattern cap overrides die with the caps. Issue #101's region-ownership concern stops affecting generation — slots filter by pattern.
- A 30-minute UPPER day is slightly push-biased (its three tier-1 slots are two presses + one pull) — accepted; balanced splits alternate focus.
- Prerequisite catalog work: the delt slots (side delts in PUSH/UPPER/ARMS, rear delts in PULL/ARMS) are unfillable until `SHOULDER_RAISE`/`REAR_DELT_FLY` exercises are seeded (0 of each in the dev catalog; verify prod). Catalog audit + seeding ships with or before the engine.
- Direct swap, no runtime engine flag: the legacy generator, its caps config, and its dead surface (`difficulty` request param — validated but never read — `formatForAI`, `calculateEstimatedDuration`, `isLowerBodyMovement`, `isolation_patterns`, `min_exercises_per_region`) are deleted in the same PR train. Emergence-pinning tests (`WorkoutGeneratorDiversityTest`, `WorkoutGeneratorArmsDayTest`) are replaced by table-driven blueprint tests; Prescription/Progression suites stand.
- Rows generated before the switch keep their stored prescriptions (same transitional posture as ADR-0009).
- Blueprints live in config, PR-reviewed; they move to the DB only if partners ever need custom blueprints.
